## 背景

当前机器上没有安装 `youdaonote` CLI，而且旧的有道云笔记 OpenAPI 路线并不适合作为默认方案。最现实的做法是：定义一个本地桥接知识源，调用用户自己安装好的 CLI/Skills 命令，把笔记导出到临时目录，再把该目录交给现有本地导入流程。

## 目标 / 非目标

**目标：**

- 在不改核心导入管线的前提下，增加一个有道桥接知识源。
- 只依赖本地 CLI，不要求库自己处理有道认证。
- 在本地 CLI 不存在或命令失败时，返回清晰错误。

**非目标：**

- 直接接入受限/废弃的有道 OpenAPI。
- 逆向私有协议。
- 在库内部管理有道登录状态。

## 决策

### 采用本地 CLI 桥接执行

库定义一个有道知识源，执行本地 `youdaonote` 命令，将笔记导出到临时目录，然后再用现有 `DirSource` 路径解析这些导出文件。

原因：
- 最大程度复用现有 `.md/.txt/.pdf` 导入能力。
- 把鉴权和账号状态留在用户本地工具里，而不是硬塞进库。
- 符合“优先使用本地 Skills/CLI，而不是新申请 OpenAPI”的现实路线。

### 桥接执行配置保持最小但显式

第一版支持：
- 命令名
- 参数模板
- 环境变量
- 工作目录

其中参数里必须显式带 `{output}` 占位符，用来接收运行时生成的临时导出目录。

原因：
- 这是最小但可工作的方案。
- 易于测试。
- 不把命令格式猜死在库里。

## 风险 / 取舍

- [不同机器上的 CLI 参数不一致] → 配置显式暴露命令和参数模板，不把某个私有命令格式硬编码成唯一方案。
- [本机没有安装 CLI] → 直接返回包含命令名的清晰错误。
- [导出目录里有不支持的文件] → 继续复用现有本地来源过滤逻辑。
